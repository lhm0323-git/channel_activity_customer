# JWT Token 解析說明

本文件說明如何解析本系統所發出的 JWT（JSON Web Token），以取得其中的職員編號（empid）與姓名（username）等資訊。此說明不限定特定程式語言，任何支援字串處理、Base64 解碼與 JSON 解析的開發環境均可依此步驟實作。

---

## 1. Token 結構

JWT 為一段以英文句點（`.`）分隔為三段的字串，格式如下：

```
Header.Payload.Signature
```

各段皆為 Base64Url 編碼字串，意義如下：

| 段落 | 名稱 | 內容說明 |
|---|---|---|
| 第 1 段 | Header（標頭） | 記錄簽章演算法（如 `HS256`）與 Token 類型（`JWT`） |
| 第 2 段 | Payload（內容） | 實際資料內容，本系統會放入職員編號、姓名等欄位 |
| 第 3 段 | Signature（簽章） | 用於驗證 Token 是否遭竄改，需搭配簽章金鑰才能驗證 |

---

## 2. 解析步驟（通用作法，不限程式語言）

1. 以英文句點 `.` 將 Token 字串切割為三段，取得 Header、Payload、Signature。
2. 將第 2 段（Payload）以 **Base64Url** 解碼（注意：非標準 Base64，若解碼失敗，通常需先將 `-`、`_` 轉換為 `+`、`/`，並視需要補上結尾的 `=` 補位字元）。
3. 將解碼後的字串以 UTF-8 文字解讀，其內容為一段 JSON 字串。
4. 將該 JSON 字串解析為物件（大多數程式語言皆內建或有現成套件可解析 JSON）。
5. 由解析後的物件中，依欄位名稱取出所需資料（例如 `empid`、`username`）。

> 備註：上述步驟僅為「讀取內容」，並未驗證 Token 是否遭竄改或是否由本系統合法簽發。若需要驗證真偽，請見第 4 節說明。

---

## 3. Payload 欄位定義

Payload 解析後會得到以下欄位（實際欄位以系統簽發當下為準，如有異動將另行通知）：

| 欄位名稱 | 型態 | 說明 |
|---|---|---|
| `userid` | 字串 | 系統內部使用者識別碼 |
| `empid` | 字串 | 員工職編（人事編號） |
| `username` | 字串 | 員工姓名 |
| `data` | 物件 | 保留欄位，供擴充使用 |
| `exp` | 數字（Unix 時間戳，秒） | Token 到期時間，需轉換為日期時間格式後判讀 |

`exp` 欄位換算方式：將該數字視為「自 1970-01-01 00:00:00 UTC 起算的秒數」，加上該秒數後即為到期時間（多數程式語言的日期時間函式庫皆提供 Unix 時間戳轉換功能）。

---

## 4. 範例（以下為示意用假資料，非實際 Token）

假設 Payload 解碼後內容如下：

```json
{
  "userid": "c000",
  "empid": "02000",
  "username": "王小明",
  "data": {},
  "exp": 1799999999
}
```

依第 2 節步驟解析後，即可直接由 JSON 物件中讀取：

- 職編：物件中 `empid` 欄位的值（範例中為 `00000`）
- 姓名：物件中 `username` 欄位的值（範例中為 `王小明`）
